# 图书商城 - 三端联动业务闭环设计

## 📋 项目概述

本文档详细说明了图书商城的**三端联动**业务闭环实现，包括：
1. **库存联动**：下单扣库存、取消/退款恢复库存
2. **角色联动**：商家查询自己订单、用户查询自己订单
3. **状态联动**：统一的订单状态流转控制

---

## 🏗️ 一、库存联动（Stock Linkage）

### 1.1 核心业务流程

```
用户下单
    ↓
验证库存是否充足
    ↓
扣减库存（stock - quantity）
增加销量（sales + quantity）
    ↓
创建订单和订单项
    ↓
订单完成
```

### 1.2 实现代码位置

**文件**：`OrderServiceImpl.java`

**核心方法**：`createOrder()` （第95-162行）

```java
// 库存扣减逻辑
book.setStock(book.getStock() - item.getQuantity());
bookService.updateById(book);

// 销量增加逻辑
book.setSales(book.getSales() + item.getQuantity());
bookService.updateById(book);
```

### 1.3 库存恢复机制

当订单取消或退款时，系统自动恢复库存：

```java
// 恢复库存逻辑（restoreStock方法）
book.setStock(book.getStock() + item.getQuantity());
book.setSales(Math.max(0, book.getSales() - item.getQuantity()));
```

**触发条件**：
- 用户取消未支付订单 → 自动恢复
- 管理员退款已支付订单 → 自动恢复

### 1.4 API 接口

无需额外接口，库存管理已在订单创建和取消流程中自动处理。

## 👥 二、角色联动（Role Linkage）

### 2.1 角色划分

系统支持三种角色，通过 `User.role` 字段区分：

| 角色 | role值 | 说明 |
|------|--------|------|
| 普通用户 | `user` | 在小程序端下单、查看自己的订单 |
| 商家 | `merchant` | 在后台管理系统查看自己店铺的订单 |
| 管理员 | `admin` | 查看所有订单 |

### 2.2 数据关联方式

#### 2.2.1 用户订单关联
- **关联字段**：`Order.userId`
- **查询方法**：`getUserOrders(userId)`
- **使用场景**：小程序端用户查看自己的订单

```java
// OrderServiceImpl.java 第45-49行
@Override
public List<Order> getUserOrders(Long userId) {
    LambdaQueryWrapper<Order> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(Order::getUserId, userId)
        .orderByDesc(Order::getCreateTime);
    return this.list(wrapper);
}
```

#### 2.2.2 商家订单关联
- **关联字段**：`OrderItem.merchantId`
- **查询方法**：`getMerchantOrders(merchantId)`
- **使用场景**：商家后台查看自己店铺的订单

```java
// OrderServiceImpl.java 第52-95行
@Override
public List<Order> getMerchantOrders(Long merchantId) {
    // 1. 查询商家所有的订单项
    LambdaQueryWrapper<OrderItem> itemWrapper = new LambdaQueryWrapper<>();
    itemWrapper.eq(OrderItem::getMerchantId, merchantId);
    List<OrderItem> merchantItems = orderItemService.list(itemWrapper);

    // 2. 获取订单ID列表
    Set<Long> orderIds = merchantItems.stream()
        .map(OrderItem::getOrderId)
        .collect(Collectors.toSet());

    // 3. 查询完整的订单信息
    LambdaQueryWrapper<Order> orderWrapper = new LambdaQueryWrapper<>();
    orderWrapper.in(Order::getId, orderIds)
        .orderByDesc(Order::getCreateTime);
    List<Order> orders = this.list(orderWrapper);

    // 4. 只返回该商家的订单项
    for (Order order : orders) {
        List<OrderItem> items = orderItemService.getOrderItems(order.getId());
        List<OrderItem> merchantSpecificItems = items.stream()
            .filter(item -> merchantId.equals(item.getMerchantId()))
            .collect(Collectors.toList());
        order.setItems(merchantSpecificItems);
    }

    return orders;
}
```

## 🔄 三、状态联动（Status Linkage）

### 3.1 订单状态流转图

```
┌──────────┐
│ pending  │ 待支付
└────┬─────┘
     │
     ├── [支付] ──────────────┐
     │                        ↓
     │                   ┌────────┐
     └── [取消] ───────→│cancelled│ 已取消
                        └────────┘

┌────────┐
│  paid  │ 已支付
└────┬───┘
     │
     ├── [发货] ──────────┐
     │                    ↓
     ├── [退款] ───────┐  ┌────────┐
     │                 ↓  │refunded │ 已退款
     └────────────────┐└────────┘
                      ↓
                 ┌──────────┐
                 │ shipped   │ 已发货
                 └────┬─────┘
                      │
                      ├── [确认收货] ──────┐
                      │                    ↓
                      │               ┌───────────┐
                      └── [超时自动]──→│ completed │ 已完成
                                         └───────────┘
```

### 3.2 状态定义

| 状态 | 中文 | 说明 | 可转换到 |
|------|------|------|----------|
| `pending` | 待支付 | 订单创建，等待用户支付 | `paid` (支付)<br>`cancelled` (取消) |
| `paid` | 已支付 | 用户已完成支付，等待商家发货 | `shipped` (发货)<br>`refunded` (退款) |
| `shipped` | 已发货 | 商家已发货，等待用户确认收货 | `completed` (完成) |
| `completed` | 已完成 | 交易完成，可评价 | 终态 |
| `cancelled` | 已取消 | 订单被取消 | 终态 |
| `refunded` | 已退款 | 已退款，库存自动恢复 | 终态 |

### 3.3 状态流转验证逻辑

**文件**：`OrderServiceImpl.java`

**核心方法**：`validateStatusTransition(currentStatus, targetStatus)` （第181-210行）

```java
@Override
public boolean validateStatusTransition(String currentStatus, String targetStatus) {
    // pending 只能转到 paid 或 cancelled
    if ("pending".equals(currentStatus)) {
        return targetStatus.equals("paid") || targetStatus.equals("cancelled");
    }

    // paid 只能转到 shipped 或 refunded
    if ("paid".equals(currentStatus)) {
        return targetStatus.equals("shipped") || targetStatus.equals("refunded");
    }

    // shipped 只能转到 completed
    if ("shipped".equals(currentStatus)) {
        return targetStatus.equals("completed");
    }

    // 其他状态不允许转换
    return false;
}
```

### 3.4 统一状态更新方法

**文件**：`OrderServiceImpl.java`

**核心方法**：`updateOrderStatus(orderId, status)` （第164-183行）

```java
@Override
@Transactional(rollbackFor = Exception.class)
public void updateOrderStatus(Long orderId, String status) throws Exception {
    Order order = this.getById(orderId);
    if (order == null) {
        throw new Exception("订单不存在");
    }

    // 验证状态流转是否合法
    if (!validateStatusTransition(order.getOrderStatus(), status)) {
        throw new Exception("不允许的状态转换: " + order.getOrderStatus() + " -> " + status);
    }

    Order updateOrder = new Order();
    updateOrder.setId(orderId);
    updateOrder.setOrderStatus(status);

    // 根据目标状态，设置相关时间戳
    if ("paid".equals(status)) {
        updateOrder.setPaymentTime(LocalDateTime.now());
    } else if ("shipped".equals(status)) {
        updateOrder.setShippingTime(LocalDateTime.now());
    } else if ("completed".equals(status)) {
        updateOrder.setCompletionTime(LocalDateTime.now());
    } else if ("cancelled".equals(status) || "refunded".equals(status)) {
        // 取消或退款时，自动恢复库存
        restoreStock(orderId);
    }

    this.updateById(updateOrder);
}
```

## 🛡️ 四、三端联动安全保障

### 4.1 事务管理

所有涉及多表操作的方法都添加了 `@Transactional` 注解：

```java
@Override
@Transactional(rollbackFor = Exception.class)
public Order createOrder(Order order) throws Exception {
    // ...
}
```

**作用**：
- 保证库存扣减、销量更新、订单创建、订单项创建的原子性
- 任何一步失败都会回滚所有操作

### 4.2 库存并发控制

虽然当前实现使用乐观锁，但建议在高并发场景下添加：

**方案1：悲观锁（推荐用于秒杀场景）**
```java
@Query("SELECT * FROM book WHERE id = #{id} FOR UPDATE")
Book selectBookForUpdate(Long id);
```

**方案2：乐观锁 + 重试机制**
```java
@Version
private Integer version;
```

### 4.3 权限验证

建议在 Controller 层添加权限验证：

```java
@GetMapping("/merchant/{merchantId}")
public Result<List<Order>> getMerchantOrders(@PathVariable Long merchantId) {
    // 验证当前用户是否为该商家
    Long currentUserId = getCurrentUserId(); // 从Session或Token获取
    User currentUser = userService.getById(currentUserId);

    if (!"merchant".equals(currentUser.getRole()) ||
        !currentUserId.equals(merchantId)) {
        return Result.error(403, "无权限访问该商家的订单");
    }

    List<Order> list = orderService.getMerchantOrders(merchantId);
    return Result.success(list);
}
```

## 📝 七、扩展建议

### 7.1 添加订单超时自动取消

**实现方案**：使用定时任务（如XXL-JOB）

```java
@XxlJob("cancelTimeoutOrderJob")
public void cancelTimeoutOrderJob() {
    // 查询超过30分钟未支付的订单
    LocalDateTime timeout = LocalDateTime.now().minusMinutes(30);
    List<Order> timeoutOrders = orderService.list(
        new LambdaQueryWrapper<Order>()
            .eq(Order::getOrderStatus, "pending")
            .lt(Order::getCreateTime, timeout)
    );

    for (Order order : timeoutOrders) {
        try {
            orderService.updateOrderStatus(order.getId(), "cancelled");
        } catch (Exception e) {
            log.error("取消超时订单失败", e);
        }
    }
}
```

@Aspect
@Component
public class OrderOperationLogAspect {

    @Around("execution(* com.bookmall.service.OrderService.updateOrderStatus(..))")
